# skill-distributor 扩展：插件级分发（枢纽 ~/.agents/plugins + symlink）

## 需求（维护者原话转述）

skill-distributor 目前只管 skill 的分发/重名检查/清理；希望扩展到**插件**层面：

1. **插件分发** —— 调研各 agent 的 plugin 扫描/安装文件夹，**在对应文件夹里创建链接**（与 skill 分发同思路：正本在仓库，链接进各 agent 目录）
2. **重复插件检查与删除** —— 对插件做 dupes/clean 同款能力
3. **同名插件用 symlink 集中到 `~/.agents/plugins` 枢纽** —— 需要调研可行性
4. **（2026-09-29 补充）GitHub 仓库直连分发**：调研 MiniMax Code 与 ZCode 能否直接支持本仓库的 GitHub 镜像（github.com/yuelezhou/my-claude-plugins-marketplace，根目录已有 `.claude-plugin/marketplace.json`）作为插件市场源——目标是「git push 即分发」，替代/简化本地目录注册与拷贝

## 已确立的事实（调研积累，2026-09-29）

- Windows 下 NTFS junction 免管理员权限，skill 层已验证可用（本插件现存机制）；symlink 需要开发者模式/管理员——若插件枢纽坚持 symlink 而非 junction，Windows 下有权限门槛
- 各 agent 的插件发现机制**与 skill 不同**：skill 有 `~/.agents/skills` 跨 agent 约定；插件没有已知的共享目录约定——Claude Code 按 marketplace 注册表安装（`~/.claude/plugins/` 下 known_marketplaces.json + marketplaces/ + repos/），ZCode 有自己的版本化缓存（`~/.zcode/cli/plugins/cache/<市场>/<插件>/<版本>/`），MiniMax 插件发现机制未调研
- 本仓库插件已三平台兼容（docs/plugin-compatibility.md），且插件正本本来就在仓库 `plugins/` 下——"分发"的实际含义待定义（见待决问题）

## 调研结论（2026-09-29，详见同目录 research.md，四/五家有一手证据）

**核心反转：原方案「各 agent 文件夹建链接」对 2/5 家不成立。**

| Agent | 插件发现目录 | 链接可用？ | 登记 | 分发动作 |
|---|---|---|---|---|
| Claude Code | 本地目录市场：`claude plugin marketplace add <仓库>` + `install 名@市场` → **原位加载**，源码改动 `/reload-plugins` 即生效；`~/.claude/skills/` 下可 `@skills-dir` 免登记 drop-in（原位加载，同名优先级最低） | 比链接更好（原位） | ①要（两条命令）②免 | 一次性注册市场 |
| ZCode | 无 drop-in 目录；`zcode plugins marketplace add` + `install`（受控实验证实装的是**缓存副本**，双登记 installed_plugins.json + enabledPlugins） | ✗ 副本制 | 必须双登记（走 CLI） | 注册市场 + 安装 + 更新时两步刷新 |
| MiniMax Code | `~/.minimax/plugins/<name>/` 物理目录放进去即自动发现、默认启用、热感知（源码级证实，五家最好的 drop-in） | **✗ junction/symlink/hardlink 一律被拒**（`PLUGIN_ROOT_SYMLINK`） | 免（sqlite 只记禁用） | **物理拷贝**，更新需重拷 |
| DeepSeek Deep Code | 无插件机制 | — | — | 插件不可分发，走 skill 通道 |
| OpenCode | `~/.config/opencode/plugins/` 但只认 JS/TS hook 模块 | — | — | Claude 式插件包不兼容，走 skill 通道 |

登记文件一律走 CLI/UI 不手改（ZCode 注册表、Claude settings、MiniMax sqlite）；项目 `.claude/plugins/` 不被 Claude 扫描；MiniMax dataDir 可被 `MINIMAX_DATA_DIR`/`MAVIS_DATA_DIR` 改写。未证实项清单见 research.md 末节。

## 调研结论二：GitHub 仓库直连（2026-09-29 追加，research.md 第 7 章，ZCode 为实机受控实验）

**「git push 即分发」判定：ZCode ✅ 可行 / Claude ✅ 可行（清单零改动合规）/ MiniMax ⚠️ 半可行。**

- **前置**：本机 HEAD（0159157，skill-distributor + demo-case 改名）尚未 push，GitHub 端清单停在旧版——推上去才有意义
- **ZCode**：`marketplace add` 支持 6 种来源形态（含 `owner/repo` 简写与 git URL，均可带 #ref）；实机实验用本仓库成功 add（识别 8 个插件）+ install hello-greeting（Claude 形态直接接受），已完整回滚。更新语义：`marketplace update` + `plugin update` 两步（重启生效）——分发器可封装
- **MiniMax**：~~Claude 兼容市场层在当前版本已不存在~~（第 8 节重验细化为：有**官方策划市场**「CC Marketplace」——云端固定源、分类/推荐齐全，但**用户不可注册自定义源**，全 asar 无任何注册端点；GitHub 能力=逐插件导入 `importGithubPlugin`，落 `~/.minimax/plugins/<名>/` 免登记自动启用；一次一个、更新=删旧+重导）。marketplace.json 对它无效。**自动化替代**：脚本直接把仓库插件目录拷进 `~/.minimax/plugins/` 与 UI 导入终态等价（第一轮已证实 drop-in 生效），绕开 UI 依赖
- **Claude 对照**：本仓库 marketplace.json 对官方 schema **零改动合规**（strict/条目 source/名称逐项核对通过），push 后 `claude plugin marketplace add yuelezhou/my-claude-plugins-marketplace` 即用

## 待决问题（调研后剩余的纯设计决策）

1. **分发策略采用矩阵**（两轮调研合并）：Claude=GitHub 市场 add（一次性，原位热更）；ZCode=GitHub 市场 add + install（封装两步更新）；MiniMax=脚本物理拷贝到 `~/.minimax/plugins/`（新鲜度指纹比对）；DeepSeek/OpenCode=只走 skill 通道——是否按此建 `link-plugins` 子命令？
2. **MiniMax 拷贝的新鲜度**：status/audit 加「MiniMax 插件副本 vs 仓库正本指纹比对」（skill 侧 dupes 同款）；clean 允许删过期副本（删前确认不变）
3. **`~/.agents/plugins` 枢纽去留**：两轮调研确认无 agent 原生扫描、插件层三范式各异——建议放弃枢纽，正本即仓库 `plugins/`，GitHub 镜像承担"分发源"角色（记入兼容矩阵文档）
4. **skill 侧 junction 不受影响**：本票不改 skill 分发机制，只新增插件层
