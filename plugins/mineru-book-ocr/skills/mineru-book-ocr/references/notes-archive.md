# 归档到读书笔记（坚果云）

MinerU 产物 → 坚果云读书笔记目录的规范与内容生成流程。机械部分由 `scripts/archive_to_notes.py` 完成，导读/TL;DR 与 Anki 卡片由模型生成。

## 目标位置与规范来源

- 笔记库根目录：`C:\Users\yuele\Documents\坚果云\文件\个人文件\笔记\编程读书笔记\`
- 目录结构规范：`<根目录>\.模板\目录结构规范_README.md`（先读它，规范以它为准）
- 归档操作规范：`<根目录>\.模板\miner_u导入模板\SKILL.md`（`archive_to_notes.py` 是它的脚本化实现）
- 书内参考范例：`<根目录>\凤凰架构：构建可靠的大型系统\`（笔记三段式、Anki deck 命名的出处）

标准书目录结构：

```
书名/
├── 原文/
│   ├── full.md        # 合并后的全文（图片路径保持 images/...）
│   ├── 章节/           # chapter-NN-标题.md（图片路径改 ../images/...）
│   └── images/        # 全书图片
├── 笔记/               # chapter-NN-标题.md，与章节一一对应
├── anki_cards/        # 每章一个 md，兼容 markdown_sync_to_anki
├── 延伸阅读/
└── _work/             # 书名_miner_u_YYYYMMDD.zip（源分片备份）
```

## 脚本做的事（archive_to_notes.py）

```bash
python scripts/archive_to_notes.py \
  --src "D:\垃圾文件夹\minuer_u未处理" --pick "书名子串" \
  --book "<笔记库根目录>\书名" --title "书名"
```

1. 从分片目录名里的 ` _N_A-B.pdf-` 解析页码区间并排序（顺序错了全文是乱的，所以不用人工排序）
2. 初始化书目录结构
3. 合并各分片 `full.md` → `原文/full.md`（分片间一个空行；跨分片被切断的章节会被自然接上）
4. **围栏感知**地按 `第N章` / `Chapter N` 拆章 → `原文/章节/chapter-NN-标题.md`，同时把图片引用改成 `../images/`。围栏感知是必须的：代码块里的 `#` 注释不能当成标题（这是凤凰架构 `_work/build_book.py` 里验证过的教训）
5. 拷贝图片（重名自动加 `_1` 后缀）
6. 生成 `笔记/` 骨架：头部引用块 + 上/下一章导航 + 空 `## 导读` / `## TL;DR`（带 TODO 注释）+ `## 问答` 占位
7. 打包源分片到 `_work/` 并校验 zip 完整性（zip 完整前**不得删源分片**）
8. 全量校验：full.md 非空、章节目录只有 .md、图片路径全部已改写、图片数量 ≥ 源合计

首个章节前的内容（版权页、目录、前言）若 ≥10 行会存成 `chapter-00-前言.md`。

## 模型接着做的事

### 1. 逐章填写笔记的导读与 TL;DR

骨架里的 TODO 注释就是要填的位置。格式照抄凤凰架构范例（读一份它的笔记再动笔）：

- **导读**：1~2 段。本章在全书中的位置与作用、核心主张、读后应建立的自觉；结尾固定给一个「带着问题读：<提问>」。
- **TL;DR**：要点 bullets，术语加粗，覆盖主干概念、机制、关键结论；是复习时的「60 秒版本」，不是目录复述。
- **问答**：**不要动**。保持 `> 本节由我提问后补充` 占位——这是用户读书时向模型提问后自己回填的部分。

写之前先读该章原文（`原文/章节/chapter-NN-*.md`）。笔记的导读/TL;DR 必须来自该章内容，不要靠书名想象。

### 2. 生成 Anki 卡片（用 anki-card-from-notes 技能）

每章一个 `anki_cards/chapter-NN-标题.md`，格式严格遵守 anki-card-from-notes 技能（`## 卡片名` + `#### 正面/背面/笔记`，或 cloze 的 `Text/Back Extra`；禁用 `###` 标题；新卡不写 `##### id`）。

配置约定（对应 anki 技能的 Step 0，一次问完）：

- **deck**：`笔记系统::计算机::<书名>::<章节名>`（与凤凰架构现有 deck 一致），首次归档时向用户确认一次，之后各章沿用
- **tags**：1~2 个主题标签（如 `[rules-engine, drools]`），同样一次确认
- **卡数**：每章 10~40 张（薄章 10 以下、厚章 30~40）
- 选卡标准：定义、机制、对比、关键数字、易混点；铺垫、口水话、纯举例不进卡
- 写完必跑 `~/.zcode/skills/anki-card-from-notes/scripts/check_anki_cards.py <文件>`，有 error 改到干净为止

### 3. 节奏

一本书通常 10~20 章，每章要通读原文 + 写笔记 + 出卡，**逐章推进**，别想着一口气写完全书。开工前和用户确认：这本书要不要全部章节都做，还是先做前几章。`chapter-00-前言` 一般只写个极简导读甚至跳过。

## 降级与坑

- **拆不出章节**（英文书常见，如 Grokking 的标题不规整）：脚本按规范降级为只保留 `full.md`，不强行拆。此时先用 `--pattern` 补充该书的章节正则重跑；仍不行就报告用户手动处理。**没有章节就没有对应的笔记/卡片骨架**，不要硬造。
- **坚果云占位文件**：目标库在坚果云同步目录里，未下载完成的文件是占位符。凡是**读**坚果云里的文件（模板、范例、已有笔记），先确认内容可读（文件大小 > 0 或能正常打开）；只**写**一般没问题，但写完的校验若读到 0 字节文件，先怀疑同步未完成而不是脚本错。
- **zip 打包时源文件被占用**：打包后必须 `testzip` 校验（脚本已做）；失败不要删源分片，等坚果云同步空闲后重试。
- **书目录已存在**：脚本默认拒绝覆盖 `原文/full.md`（加 `--overwrite` 才覆盖）；重复归档前先看已有内容是不是已经人工加工过（笔记填过导读的章节别被骨架覆盖——脚本不会覆盖已有笔记，但 `--overwrite` 重跑会重写章节文件，人工改过的章节会丢）。
