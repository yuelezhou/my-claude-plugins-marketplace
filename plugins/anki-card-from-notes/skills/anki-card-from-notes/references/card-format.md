# 完整卡片格式契约

这是 `markdown_sync_to_anki` 同步工具（或 Obsidian Anki 插件）解析的完整格式规范。`SKILL.md` 里的 Procedure 和 Output contract 是这份规范的摘要；这里写完整版，用于对照和出错排查。

## 文件由两部分组成

### 一、文件头（YAML frontmatter）

文件最开头用 `---` 包围的 YAML 块：

```yaml
---
anki: true
deck: <牌组名，支持 :: 层级，如 编程::JavaScript>
tags: [<标签1>, <标签2>]
note_type: 正面-背面-笔记
---
```

字段说明：
- **`anki: true`（必填）**：标记此文件是 Anki 卡片源。没有这行的 .md 不会被同步（避免误扫普通笔记）
- **`deck`**：该文件所有卡片默认进这个牌组
- **`tags`**：该文件所有卡片默认带这些标签（YAML 数组或逗号字符串均可）
- **`note_type`**：该文件所有卡片默认用这个类型（默认 basic）

### 二、卡片（用标题层级表达结构）

#### 标题层级语义（必须严格遵守）

| 层级 | 作用 | 是否进入 Anki |
|------|------|---------------|
| `## 二级标题` | 一张卡片（在 Obsidian 内的导航名） | ❌ 不进 Anki，只是卡片的名字 |
| `#### 四级标题` | 字段类别（如「正面」「背面」「Text」） | ✅ 字段内容进 Anki |
| `#### 元数据` | 特殊字段，其下的五级标题携带卡片级覆盖 | ❌ 不进 Anki |
| `##### 五级标题` | 元数据键（仅 `#### 元数据` 下有效） | ❌ 作为控制信息 |

#### 卡片类型与字段

**Basic 类型**（问答卡，正面提问、背面回答）：
- 字段：`正面`（必需）、`背面`（必需）、`笔记`（可选补充）
- 复习时正面只显示「正面」字段；翻面后显示 正面 / 背面 / 笔记 三段

**Cloze 类型**（完形填空，挖空记忆）：
- 字段：`Text`（必需，含挖空标记）、`Back Extra`（可选补充）
- 挖空语法：`{{c1::被挖的内容}}`、`{{c2::第二个挖空}}`，编号可多个

#### 卡片级覆盖（可选）

在卡片末尾用 `#### 元数据` 段，其下的 `#####` 五级标题覆盖文件级默认值：

```
#### 元数据
##### deck
<覆盖的牌组>
##### tags
<逗号分隔的覆盖标签>
##### note_type
<basic 或 cloze>
##### id
<已有的 Anki 卡片 ID，仅同步过的卡片才有，新卡不要写>
```

#### 允许的富文本

字段正文里可以使用：
- **加粗**、*斜体*、~~删除线~~
- 代码块：```js ... ```（请标注语言）
- 行内代码：`code`
- 数学公式：行内 `$E=mc^2$`，块级 `$$\int_0^1 x\,dx$$`
- 表格（标准 GFM 语法）
- 列表（有序 / 无序）

## 严格禁止

- ❌ 不要写一级标题 `#`、三级标题 `###`、六级标题 `######`（解析器会忽略，但不应该出现）
- ❌ 不要在代码块 ``` 里写 `## ` / `#### ` 开头的行（会被误识别；如果必须写，请用 4 空格缩进代码块代替）
- ❌ 字段名只能是：`正面` / `背面` / `笔记` / `Text` / `Back Extra` / `元数据`。其他名字会报错
- ❌ 不要给新卡片写 `##### id`（ID 由同步工具在首次推送后自动回写）
- ❌ Cloze 卡片的 `Text` 字段必须至少包含一个 `{{c1::...}}` 挖空
- ❌ Basic 卡片必须有 `正面` 和 `背面` 两个字段

## 完整范例

### 范例一：最简 Basic 卡片

```markdown
---
anki: true
deck: 示例::通用
tags: [example]
note_type: basic
---

## 范例一：最简 Basic 卡片

#### 正面
TCP 三次握手的目的是什么？

#### 背面
在通信双方之间**建立可靠连接**，同步双方的序列号（SYN）。

#### 笔记
TCP 是面向连接、可靠、有序的协议。
```

### 范例二：Cloze 填空

```markdown
---
anki: true
deck: 示例::通用
tags: [example]
note_type: basic
---

## 范例二：Cloze 填空

#### Text
三次握手依次发送 {{c1::SYN}}、{{c2::SYN-ACK}}、{{c3::ACK}}。

#### Back Extra
SYN = 同步，ACK = 确认。

#### 元数据
##### note_type
cloze
```

### 范例三：全字段范例（3 内容字段 + 4 元数据键全齐）

```markdown
---
anki: true
deck: 示例::通用
tags: [example]
note_type: basic
---

## 范例三：全字段范例

#### 正面
OSI 七层模型从下到上依次是哪七层？

支持**富文本**：物理层、数据链路层、网络层、传输层、会话层、表示层、应用层。

#### 背面
记忆口诀：**物、数、网、传、会、表、应**。

| 层级 | 英文 | 典型协议 |
|------|------|----------|
| 物理层 | Physical | Ethernet |
| 传输层 | Transport | TCP / UDP |

#### 笔记
实际工程常用 TCP/IP 四层模型，OSI 是理论参考。

#### 元数据
##### deck
计算机::网络::基础
##### tags
network, osi, layered-model
##### note_type
basic
```

## 同步工具说明

- 同步工具：`md2anki sync`（CLI）或 Obsidian Anki 插件
- ID 回写：首次同步成功后，工具会把 Anki 返回的卡片 ID 自动写入 `#### 元数据 / ##### id`，再次同步时不会重复创建
- 格式契约的权威来源：仓库根目录的 `SPEC.md`（若该 skill 用于某具体仓库）
- 机器校验：交付前可运行 skill 附带的 `scripts/check_anki_cards.py <文件>`，覆盖以上全部硬性约束，报错带行号（`error` 必改，`warning` 视情况）
