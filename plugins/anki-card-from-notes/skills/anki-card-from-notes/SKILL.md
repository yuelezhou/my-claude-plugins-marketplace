# Anki Card From Notes

按 `markdown_sync_to_anki` 格式把笔记转成 Anki 卡片 markdown，可直接走同步工具推到 Anki。完整格式契约见 `references/card-format.md`，本文只列执行规则。

## Inputs to collect

- **笔记正文**：用户提供的源材料（讲义 / 书摘 / 文章 / Obsidian 笔记 / 课堂笔记）
- **deck 名**：用户没指定时用 `编程::<资料名>::第X章` 风格（参考用户偏好）；完全不指定则用 `未分类`
- **tags**：用户没指定时给 1-2 个与主题相关的标签，多了反而稀释复习
- **卡数期望**：用户没指定时按"每章 10-40 张"——章节薄就 10 张以下，厚就 30-40 张；宁少勿凑

如果用户没把内容贴出来（比如只说"做 Anki 卡片"），先问清楚范围再开工。

## Procedure

1. **先看后写**：通读笔记，识别"值得记"的知识点清单
   - 入选标准：定义、机制、对比、关键数字、易混点、源码片段、协议字段
   - 排除：铺垫、口水话、次要事实、纯举例、过渡段
   - 原因：每张卡复习时是固定成本，杂事塞进去拖累记忆曲线

2. **选卡片类型**（字段细则见 `references/card-format.md`）
   - **Basic（问答）**：定义、列举、对比、why-how 解释、原理类问题
   - **Cloze（挖空）**：易忘术语、固定数字、流程步骤、含"填空感"的语句
   - 同一知识点原则上只出 1 张卡，避免重复刷；只有刻意要强化才做 Basic + Cloze 配对

3. **写字段**（字段名严格用中文 `正面/背面/笔记` 或 `Text/Back Extra`，不要造词）
   - 正面：一个问题，简洁明确（一句话能问清就别用两句话）
   - 背面：完整准确的答案；性能/对比题必须说明"在什么场景下 A 比 B 好"，不写"看情况"
   - 笔记：补充记忆口诀、易混点、与其他卡片的关联、可选
   - 字段正文允许的富文本：加粗/斜体/删除、行内代码、代码块（标语言）、行内数学 `$...$`、块级 `$$...$$`、GFM 表格、有序/无序列表
   - 原因：Anki 复习时卡片不富文本会很枯燥；正面要克制、背面要充分

4. **只有需要覆盖文件级默认值时才加 `#### 元数据` 段**
   - 例：本卡要进不同 deck / 加额外 tag / 改用 cloze
   - 不需要就别写，保持文件干净

5. **frontmatter 必含 `anki: true`**，缺它同步工具不扫
   - `deck` / `tags` / `note_type` 写文件级默认

6. **整份输出只给一个 markdown 代码块**，代码块外不做解释
   - 原因：方便用户直接复制到 .md 文件

## Output contract

每份输出是一个完整的 .md 文件，路径由用户决定（常见位置：
`<workspace>/Anki/<资料名>/<章节或主题>.md`）。

最小骨架：

```markdown
---
anki: true
deck: <牌组，支持 :: 层级>
tags: [<tag1>, <tag2>]
note_type: basic       # 或 cloze
---

## <卡片名 1>（只在 Obsidian 里的导航名，不进 Anki）

#### 正面
<问题>

#### 背面
<回答>

#### 笔记（可选）
<补充>

## <卡片名 2>
...（重复 N 张）

#### 元数据（仅当本卡覆盖文件默认值时用）
##### deck
<覆盖的 deck>
##### tags
<覆盖的 tags，逗号分隔>
##### note_type
<basic 或 cloze>
##### id
<不要写新卡的 id！id 由同步工具在首次推送后自动回写>
```

**硬性约束**（违反会同步失败）：
- ❌ 不要用 `#` `###` `######` 标题
- ❌ 代码块里别再写 `## ` `#### ` 开头的行（会误识别），如必须，用 4 空格缩进代码块
- ❌ 字段名只能是 `正面 / 背面 / 笔记 / Text / Back Extra / 元数据`，其他名字报错
- ❌ Cloze 的 `Text` 必须至少 1 个 `{{c1::...}}` 挖空
- ❌ Basic 必须有 `正面` 和 `背面`
- ❌ 不要给新卡写 `##### id`

完整格式契约 + 详细范例见 `references/card-format.md`。

## Failure handling

- **同步报错** → 报错信息回贴，按"硬性约束"清单自查修正
- **挖空语法错**（漏 `::`、编号错乱） → 重新数 c1/c2/c3 顺序
- **frontmatter 漏 `anki: true`** → 直接补上
- **cloze 卡但没挖空** → 改成 basic，或真要 cloze 就加 `{{c1::...}}`
- **用户要 .apkg / .txt** → 提示：本 skill 只产 markdown，导出靠 Anki 自带导入器或 `md2anki` 转换脚本
- **章节太短（< 200 字）** → 出 2-5 张关键卡，不硬凑
- **章节太厚（> 5000 字）** → 拆 2-3 个文件，按"主题"或"小节"分组
- **笔记里出现一级标题 / 代码块里塞 `## `** → 重写，挪到代码块外或改用 4 空格缩进

## Examples

**Input**：用户说"把这段《算法导论》第 12 章 BST 的讲义转 Anki 卡片，deck 用 `编程::算法导论::第12章`，tags 用 `algo,bst`"。

**Output**：

```markdown
---
anki: true
deck: 编程::算法导论::第12章
tags: [algo, bst]
note_type: basic
---

## BST 的中序遍历有序性

#### 正面
BST 的中序遍历为什么能给出有序序列？

#### 背面
因为 BST 的不变量是「左子树 < 根 < 右子树」，中序遍历顺序访问时先左、再根、再右，每次都先访问更小的，所以全局有序。

#### 笔记
这是 BST 能做有序统计查询（rank/select）和作为有序集合底层结构的根本原因。
```

完整 3-范例对照（最简 Basic、Cloze、全字段范例）见 `references/card-format.md`。
